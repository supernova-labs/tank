# Referências para uma biblioteca de "retrieval with evidence"

Pesquisa feita em 2026-09-02 (docs, READMEs e código-fonte verificados; stars/releases via GitHub API). Cobre 20+ projetos; organizada por família, com tabela comparativa, lacunas honestas e recomendações de reuso ao final.

## 1. Frameworks gerais

### LlamaIndex (MIT, 52k★, v0.14.24 2026-08-19)
Unidade = `BaseNode`/`TextNode` (pydantic). Tem `relationships` (SOURCE/PREVIOUS/NEXT/PARENT/CHILD), `excluded_embed_metadata_keys` vs `excluded_llm_metadata_keys` e `get_content(MetadataMode.EMBED|LLM)` — a separação `text_for_embedding`/`text_for_context` existe, mas como *filtro de metadata sobre um texto só*, não como dois campos independentes ([schema.py](https://github.com/run-llama/llama_index/blob/main/llama-index-core/llama_index/core/schema.py)). Subclassear `BaseNode` é possível, mas o ecossistema assume `TextNode`. Ids: `uuid4` por default; determinístico só com `filename_as_id`/`id_func`. `hash = sha256(text + str(metadata))`. `RelatedNodeInfo` guarda o `hash` do nó de origem na aresta — um "DerivationIntact" barato que ninguém usa. `IngestionPipeline` com `DocstoreStrategy.UPSERTS / DUPLICATES_ONLY / UPSERTS_AND_DELETE` via mapa `doc_id → hash` ([pipeline.py](https://github.com/run-llama/llama_index/blob/main/llama-index-core/llama_index/core/ingestion/pipeline.py)); só o id do *documento* é estável, chunks ganham uuids novos a cada reprocessamento; UPSERTS silenciosamente vira DUPLICATES_ONLY sem vector store. `CitationQueryEngine` re-divide os nós em sub-chunks "Source N:" e pede `[n]` ao LLM; **não parseia nem valida nada** ([citation_query_engine.py](https://github.com/run-llama/llama_index/blob/main/llama-index-core/llama_index/core/query_engine/citation_query_engine.py)). Híbrido: `QueryFusionRetriever` com `reciprocal_rerank` (k=60), `relative_score` (min-max × pesos), `dist_based_score` (mean±3σ), dedup por `node.hash` ([fusion_retriever.py](https://github.com/run-llama/llama_index/blob/main/llama-index-core/llama_index/core/retrievers/fusion_retriever.py)); `BM25Retriever` via `bm25s`. Eval: `Faithfulness/Relevancy` (YES/NO), `Correctness` (1–5), `RetrieverEvaluator` (hit_rate, mrr, precision, recall, ap, ndcg — **todas por id exato de nó**), `generate_question_context_pairs`, `LabelledRagDataset`. Storage: `StorageContext`; **sem SurrealDB oficial** — a própria SurrealDB publica um adapter de 20 linhas ([guia](https://surrealdb.com/docs/integrations/frameworks/llama-index)).

### Haystack 3.x (Apache-2.0, 26k★, v3.1.0 2026-08-24)
`Document` é dataclass concreta, **não plugável**; `id = sha256(content + json.dumps(meta, sort_keys) + blob + embedding…)` — determinístico, mas id == hash, logo "mesma unidade, nova versão" é inexprimível ([document.py](https://github.com/deepset-ai/haystack/blob/main/haystack/dataclasses/document.py)). `DocumentJoiner` com `concatenate / merge / reciprocal_rank_fusion (k=61, ponderado) / distribution_based_rank_fusion` ([misc.py](https://github.com/deepset-ai/haystack/blob/main/haystack/utils/misc.py)); `DuplicatePolicy` SKIP/OVERWRITE/FAIL. Citações: só `AnswerBuilder(reference_pattern)` — regex `[n]`, checa apenas o range do índice e *avisa* sem descartar ([answer_builder.py](https://github.com/deepset-ai/haystack/blob/main/haystack/components/builders/answer_builder.py)); o `ReferencePredictor` (cross-encoder alinhando sentenças) é enterprise-only e **deprecado** ([docs](https://docs.cloud.deepset.ai/docs/referencepredictor)). Proveniência = meta strings (`source_id`, `split_id`, `split_idx_start`, `__parent_id`). Eval: `FaithfulnessEvaluator` **por statement**, `ContextRelevance`, Recall/MAP/MRR/NDCG, `EvaluationRunResult.comparative_detailed_report`. `DocumentStore` é `typing.Protocol` mínimo (write/filter/delete) com retrievers específicos por store — bom modelo. Sem SurrealDB.

## 2. Plataformas RAG

### R2R / SciPhi (MIT, 8k★, PyPI 3.6.6 2025-08; **dormente** desde 2025-11, empresa pivotou)
Unidade fixa: tabela `chunks` no Postgres. Ids `uuid5` posicionais (`doc_id + índice + "v0"`); `version` nunca incrementa; re-ingest = 409. Citações `[c910e2e]` (prefixo de 7 chars do uuid), extração por regex, resolução por `startswith` linear; **ids desconhecidos ficam com `payload=None`** ([utils](https://github.com/SciPhi-AI/R2R/blob/main/py/core/utils/__init__.py)); eventos SSE `citation{id,is_new,span,payload}` bem desenhados. Híbrido: tsvector + pgvector, RRF em Python com `semantic_weight=5, full_text_weight=1, rrf_k=50`. Grafo guarda `chunk_ids[]` em entidades **mas a busca nunca os retorna**. Sem eval.

### Cognita / TrueFoundry (Apache-2.0, 4.4k★, **arquivado 2026-03-13**)
Unidade = LangChain `Document`; parser = chunker (registry por extensão). Sync incremental lê `{fqn: hash}` do vector DB (único ledger), pula iguais; o "hash" é `str(os.lstat())` ou `size:updated_at`, não conteúdo; chunk ids uuid aleatórios a cada upsert; INCREMENTAL nunca remove deletados ([indexer.py](https://github.com/truefoundry/cognita/blob/main/backend/indexer/indexer.py)). Sem citações inline, sem híbrido, sem eval. Reuso: snapshot de `parser_config` por ingestion run.

### kotaemon / Cinnamon (Apache-2.0, 25.7k★, v0.12.0 2026-05; cadência lenta)
Unidade = nó llama-index; ids uuid4; dedup **por nome de arquivo** (sha256 calculado mas só usado como path). Modo `highlight`: `CitationPipeline` roda em thread paralela ao stream, tool-call forçada `CiteEvidence{evidences: List[str]}` ("substring, ≤15 palavras"), com **timeout de 5 s que descarta silenciosamente**; matching via `difflib.SequenceMatcher` com aceitação em ~35 % do comprimento ([citation.py](https://github.com/Cinnamon/kotaemon/blob/main/libs/kotaemon/kotaemon/indices/qa/citation.py), [utils.py](https://github.com/Cinnamon/kotaemon/blob/main/libs/kotaemon/kotaemon/indices/qa/utils.py)). Modo `inline`: `【n】` + `START_PHRASE/END_PHRASE` (~6 palavras), `replace_citation_with_link` **não checa se n existe**. PDF.js destaca por LCS ratio > 0,5 nos spans da text-layer. "Hybrid" = concatenação (FTS com score −1 + vetor), sem RRF. Evidência de grafo (GraphRAG/LightRAG) vem como tabelas markdown **sem file_id/página**. Sem eval.

### Onyx / ex-Danswer (MIT + EE, 31.9k★, v4.6.5 2026-08-29; muito ativo)
OpenSearch é o índice default (Vespa legado). `DocAwareChunk` com `mini_chunk_texts`, `large_chunk_id`, `doc_summary`/`chunk_context` (contextual RAG) ([models.py](https://github.com/onyx-dot-app/onyx/blob/main/backend/onyx/indexing/models.py)). Ids determinísticos: `"{document_id}__{max_chunk_size}__{chunk_index}"`. Re-index com **duas gates**: `doc_updated_at` e depois `content_hash` (MD5 título+seções+meta), gravado só após escrita bem-sucedida; chunks obsoletos removidos por diff de `chunk_count` ([indexing_pipeline.py](https://github.com/onyx-dot-app/onyx/blob/main/backend/onyx/indexing/indexing_pipeline.py)). Citações `[n]` **um número por documento**; `DynamicCitationProcessor` faz hold-back de marcadores parciais no stream, ignora code blocks, **descarta números fora do mapping com warning** ([citation_processor.py](https://github.com/onyx-dot-app/onyx/blob/main/backend/onyx/chat/citation_processor.py)); nenhuma verificação de span. Híbrido OpenSearch: `knn + multi_match` com min-max e `arithmetic_mean` **fixo 0,5/0,5**, `HYBRID_ALPHA` inerte, sem decay/boost (README do módulo explica honestamente por quê). Eval: `tests/regression/search_quality` com `{question, ground_truth:[{doc_source, doc_link}]}`; sem métrica de citação.

### RAGFlow / InfiniFlow (Apache-2.0, 89.9k★, v0.27.1 2026-08-28; muito ativo)
Unidade = linha de chunk plana com vocabulário rico: `position_int` (5-tuplas `[page,x0,x1,top,bottom]`), `mom_id` (pai), `source_id`, `chunk_hash_kwd`, `important_kwd`, `question_kwd`, `raptor_layer_int` ([infinity_mapping.json](https://github.com/infiniflow/ragflow/blob/main/conf/infinity_mapping.json)). 15 templates de chunking plugáveis como *produtores*; unidade fixa. Chunk id = `xxh64(content + doc_id)`; re-parse reusa por `digest` da config. Citações em **dois níveis**: (a) prompt `[ID:i]` com validação de range + `repair_bad_citation_formats`; (b) fallback pós-hoc **só quando o LLM não emitiu nenhum marcador**: `insert_citations` divide em sentenças (protege code fences), embeda, calcula `cosine·vt + token_sim·tk` (0,3/0,7), threshold adaptativo 0,63→×0,8 até 0,3, top-1 + near-ties cap 4 ([search.py](https://github.com/infiniflow/ragflow/blob/main/rag/nlp/search.py)). No caminho principal **não há verificação semântica**; `reference.chunks` devolve *todos* os recuperados. Híbrido: Infinity nativo `weighted_sum` (atan-norm); ES faz segunda passada KNN e blend client-side + `rank_feature` (PageRank/tags); abstração `MatchTextExpr/MatchDenseExpr/FusionExpr` engine-agnóstica. KG guarda `source_id` mas o retrieval injeta um chunk sintético `doc_id: ""` — proveniência perdida. Sem eval (só "retrieval testing" manual).

## 3. Grafos e txtai

### Microsoft GraphRAG (MIT, 35.8k★, v3.1.2 2026-08-21; "maintenance mode")
Tabelas parquet `documents / text_units / entities / relationships / communities / community_reports`. Ids = `sha512(text)` (docs dizem uuid, código diz hash — **colide entre documentos com texto igual**). Proveniência real: `entities.text_unit_ids`, `relationships.text_unit_ids`, `communities.text_unit_ids` ([outputs](https://microsoft.github.io/graphrag/index/outputs/)). Padrão duplo `id` opaco + `human_readable_id` curto por run, usado só em citações `[Data: Reports (12); Entities (5)]` — **impostas por prompt, nunca validadas** ([discussion #800](https://github.com/microsoft/graphrag/discussions/800)). `graphrag update` faz delta + `entity_id_mapping` em pasta separada. Sem BM25; eval externo (BenchmarkQED).

### LightRAG (MIT, 39.3k★, v1.5.7 2026-09-02)
Ids `doc-md5(text)`, chunks **doc-scoped e length-prefixed** `md5(f"{len(doc_key)}:{doc_key}:{chunk}")` com comentário explicando a colisão que evita ([utils_pipeline.py](https://github.com/HKUDS/LightRAG/blob/main/lightrag/utils_pipeline.py)); política de compat de hash entre versões. Entidades/relações carregam `source_id` = chunk ids unidos por `<SEP>`, com cap `max_source_ids_per_entity`. Desde v1.4.9 responde `references[]` + footnotes `[^n]` numeradas **por `file_path`** (não por chunk), sem parser/validação. "hybrid" = grafo + vetor, sem BM25. Eval: scripts RAGAS.

### txtai (Apache-2.0, 12.9k★, v9.13.0 2026-08-27)
`Embeddings` acopla content store (SQLite/DuckDB) + ANN + BM25 + grafo. Fusão **escolhida pelo tipo de normalização do sparse**: BB25/bayes → log-odds; `normalize:true` → combinação convexa; senão RRF com k=0 ([hybrid.py](https://github.com/neuml/txtai/blob/master/src/python/txtai/embeddings/search/hybrid.py)). SQL sobre o índice (`WHERE similar('q', 0.5) AND flag=1`) é ótima superfície para scope keys. `RAG(output="reference")` só devolve o id usado. Sem eval, sem verificação.

## 4. Storage (breve)
- **LanceDB**: híbrido = vetor + FTS depois `RRFReranker` (default) / `LinearCombinationReranker` (weight 0,7) / cross-encoders; `return_score="all"` expõe `_distance` e `_score`; `merge_insert(key)` para upsert; versionamento git-like de tabelas ([docs](https://docs.lancedb.com/search/hybrid-search)).
- **Chroma** (1.5.9): ids do usuário, `upsert`; híbrido via `SparseVectorIndexConfig` + `Rrf(weights, k=60)`, docs cloud-first ([docs](https://docs.trychroma.com/cloud/search-api/hybrid-search)).
- **Weaviate**: `alpha`, `relativeScoreFusion` (default) vs `rankedFusion`, `generate_uuid5`; único com `explain_score` textual (bm25 vs vector) ([docs](https://docs.weaviate.io/weaviate/search/hybrid)).
- **SurrealDB 3.x**: HNSW/DiskANN com `<|K,EF|>`; `FULLTEXT ANALYZER … BM25 HIGHLIGHTS` (uma field por índice), `search::score/highlight/offsets` (offsets `{s,e}` por termo); **fusão nativa `search::rrf($lists, $limit, $k)` e `search::linear($lists, $weights, $limit, 'minmax'|'zscore')`** ([search functions](https://surrealdb.com/docs/surrealql/functions/database/search), [exemplo real](https://surrealdb.com/blog/a-real-world-example-of-hybrid-fusion-search-using-the-surrealdb-docs-search)); sem reranker nativo; `VERSION` time-travel é alpha e engine-gated — **receipts precisam de hash/versão próprios**. Gotcha: IDF do BM25 zera para termos em ≥50 % dos docs (corpora pequenos). Bibliotecas Python existentes: `langchain-surrealdb` oficial (vector-only, 32★), `surrealdb/kaig` (experimental), `taro` (hackathon; chega sozinho em `find` preview → `cat` registro completo), `surreal-memory`, notebooks. **Nada library-grade**; a SurrealDB tem o produto fechado **Spectron / Agent Memory** (RRF k=60 + graph rerank, "first-class provenance") — verificar licença/SDK antes de posicionar ([docs](https://surrealdb.com/docs/agent-memory)).

| **Cohere Chat v2** ([docs](https://docs.cohere.com/docs/rag-citations)) | offsets na *resposta* + `sources[]`; modos FAST/ACCURATE/OFF | Não; ACCURATE é segunda passada do modelo |
| **Gemini groundingMetadata** | byte offsets na resposta; `confidenceScores` vazio em 2.5+ | Não |
| **Vertex AI Check Grounding** ([docs](https://docs.cloud.google.com/generative-ai-app-builder/docs/check-grounding)) | por claim: `startPos/endPos`, `citationIndices`, `antiCitationIndices`, `score`, `groundingCheckRequired`; `citationThreshold` 0,6; claim parcialmente verdadeira = zero citações | **Sim** — serviço pós-hoc de entailment; o análogo mais próximo do `DerivationIntact` |
| **Vectara** ([HHEM](https://huggingface.co/vectara/hallucination_evaluation_model)) | `[n]` gerado pelo LLM; `factual_consistency_score` pelo HHEM sobre a resposta inteira; `lexical_interpolation` λ (default 0, recomendado 0,01–0,1); "core documents" com `document_parts[]` 1:1 com embedding + `context` por parte | Citação não; factualidade sim, granularidade resposta inteira. HHEM-2.1-open é Apache-2.0, ~600 MB, CPU, alta precisão/baixo recall |

**Anthropic Contextual Retrieval**: prepend de 50–100 tokens de contexto gerado por LLM antes de embedar *e* indexar em BM25; −35 % (embeddings) / −49 % (+BM25) / −67 % (+rerank) na falha top-20; cookbook usa `0.8·1/(rank+1) + 0.2·1/(rank+1)` com pool 150 ([post](https://www.anthropic.com/news/contextual-retrieval), [cookbook](https://platform.claude.com/cookbook/capabilities-contextual-embeddings-guide)). Replicação independente (T2-RAGBench, 2026) acha +2 pp sobre híbrido RRF e que o reranker domina ([arXiv](https://arxiv.org/html/2604.01733v1)). É exatamente `text_for_embedding ≠ text_for_context` — e o contexto gerado deveria ser uma aresta `generated_from` re-verificável.

## 6. Avaliação
- **Ragas** (Apache-2.0, 15.6k★, v0.4.3 2026-01; **repo parado desde 2026-02, 224 PRs abertos**): Faithfulness (claims + NLI), `FaithfulnesswithHHEM`, ContextPrecision/Recall (LLM e não-LLM), NoiseSensitivity, FactualCorrectness, métricas NVIDIA (`ResponseGroundedness`); **`QuotedSpansAlignment`** = QuoteMatch verbatim não-LLM ([metric.py](https://github.com/vibrantlabsai/ragas/blob/main/src/ragas/metrics/collections/quoted_spans/metric.py)); `TestsetGenerator` por knowledge graph (single/multi-hop, personas) — pinar ou vendorizar.
- **TruLens** (MIT, 3.5k★, 2.13.1 2026-08-20, muito ativo): RAG Triad; groundedness sentença-a-sentença (LLM 0–3 ou DocNLI); **novos `citation_attribution` (binário `[N]` aponta para a passagem que suporta *aquele* claim) e `citation_accuracy` (0–3)**, jul/ago 2026 ([llm_provider.py](https://github.com/truera/trulens/blob/main/src/feedback/trulens/feedback/llm_provider.py)). A separação groundedness (suportado em algum lugar) vs attribution (suportado pela citação) é exatamente candidate ≠ evidence.
- **DeepEval** (Apache-2.0, 18.1k★, v4.2.0 2026-08-24): `LLMTestCase{context (ideal), retrieval_context (real)}`, G-Eval com rubric, **`DAGMetric`** (árvore de nós de julgamento — bom molde para QuoteMatch→DerivationIntact→Recompute), `CitationFaithfulnessMetric` (community, binário), `Synthesizer` com 7 evoluções.
- **FlashRAG** (MIT, 3.6k★, v0.3.0 2025-08): toolkit acadêmico; `retrieval_recall` = *string containment* da resposta, não qrels — não copiar.
- Referências de métrica de citação: **ALCE** (citation recall = entailment conjunto; precision = teste "remove-one", NLI T5-xxl) ([eval.py](https://raw.githubusercontent.com/princeton-nlp/ALCE/main/eval.py)); RAGChecker (claim-level, Apache-2.0); RefChecker (**arquivado 2026-04**); **MiniCheck** (Apache-2.0, flan-t5-large ≈ GPT-4; Bespoke-7B é CC-BY-NC); **LettuceDetect** (MIT, 601★, 0.2.3 2026-08, spans de caractere não suportados, ModernBERT/EuroBERT); LongTracer (STS + cross-encoder NLI sem LLM); Vectara open-rag-eval (UMBRELA, nuggets, métrica de citação por sentença). IR: **ranx** (recall@k/MRR/nDCG + 25 fusões incl. RRF, testes estatísticos) e ir-measures.

## 7. Quem faz as partes distintivas?
- **QuoteMatch (substring exata)**: o padrão canônico é o validator Pydantic do **Instructor** (`re.finditer(re.escape(quote), context)`) — mas *descarta* em falha ([exact_citations](https://python.useinstructor.com/examples/exact_citations/)); `FuzzyCitationEnginePack` do LlamaIndex (thefuzz, threshold 50); kotaemon (difflib 35 %). Ninguém marca-sem-descartar.
- **Candidate ≠ evidence**: paper-qa (Apache-2.0, 9.1k★) tem `gather_evidence` → `Context` pontuado → resposta cita `pqac-…`, mas evidência = resumo LLM, sem hash; contrato MCP do OpenAI Deep Research exige `search → {ids}` e `fetch(id)` ([docs](https://platform.openai.com/docs/guides/deep-research)); AgenticRAG `search/open/find`. Todos por *orçamento de contexto*, nenhum por citabilidade/receipt.
- **Projeção de índice sobre DB existente**: **pgai Vectorizer** (`create_vectorizer(source_table, loading, chunking, formatting template, destination)` + fila/worker + cascade) é o modelo mais próximo, Postgres-only e chunk-first ([docs](https://github.com/timescale/pgai/blob/main/docs/vectorizer/overview.md)); Azure AI Search index projections (rotação de chave quando pai muda); Superlinked **arquivado 2026-05**; cognee/Graphiti têm proveniência mas donos do modelo.
- **Proveniência**: W3C PROV-O já tem `wasDerivedFrom`/`wasGeneratedBy` ([spec](https://www.w3.org/TR/prov-o/)); nenhuma lib RAG traz `supported_by` como aresta verificada.

## 9. O que ninguém faz (honestamente)
1. **Verificação polimórfica por tipo de unidade** (QuoteMatch / DerivationIntact / Recompute): inexistente. Cada ferramenta assume uma granularidade e um método. Peças isoladas existem: Instructor (exata), kotaemon/FuzzyCitation (fuzzy), Vertex Check Grounding / HHEM / MiniCheck / LettuceDetect (entailment), llmware `evidence_check_numbers` e rag-citation (heurísticas numéricas/entidades ≈ Recompute-lite). **Recompute com id determinístico para fatos computados**: nada.
2. **Candidate ≠ evidence com receipt (hash + versão) na abertura**: ninguém. Hashes são usados para dedup/refresh (Haystack, LlamaIndex, Onyx, Azure), nunca como recibo de citação. Anthropic garante ponteiro válido *dentro de uma chamada*; não há persistência.
3. **"Rodar por default, marcar falhas sem descartar"**: o mais próximo é `AnswerBuilder` do Haystack (avisa e mantém) e Onyx (descarta com warning). kotaemon e Instructor descartam silenciosamente; R2R mantém com payload nulo.
4. **Unidade como protocolo**: todos expõem classe concreta (Document/TextNode/chunk row). Anthropic custom-content blocks e Vectara `document_parts` são unit-agnostic, mas não são protocolo Python.
5. **Proveniência atravessando o retrieval**: GraphRAG, LightRAG, R2R e RAGFlow *armazenam* `text_unit_ids/source_id/chunk_ids`, mas R2R, RAGFlow e kotaemon **perdem isso na resposta**. `supported_by` como aresta verificada não existe em lugar nenhum.
6. **Fusão medida**: todo mundo hardcoda (5:1, 0,5/0,5, 0,7/0,3, 0,8/0,2); só txtai escolhe a estratégia por calibração e só o README do Onyx discute o trade-off. Nenhuma lib acopla eval ao ajuste da fusão.
7. **Projeção sobre DB existente com ontologia + renderers**: pgai é o único precedente sério e é Postgres/SQL/chunk-first. Sobre SurrealDB: zero.

O que **já existe** e não deve ser reinventado: fusão nativa (`search::rrf/linear` no SurrealDB), métricas IR (ranx), NLI local (HHEM/MiniCheck/LettuceDetect), formato de evento de citação em stream (R2R/Onyx), geração de golden sets (Ragas/DeepEval).

## 10. Recomendações de reuso
1. **Fusão dentro do SurrealDB**: usar `search::rrf` / `search::linear` (≥3.0) com o padrão 4 listas (page+section × FTS/vector) do [docs-search da SurrealDB](https://surrealdb.com/blog/a-real-world-example-of-hybrid-fusion-search-using-the-surrealdb-docs-search); manter reranker em Python via esperanto. Scope filter entra no `WHERE` do KNN (avaliado durante a travessia HNSW) e no `@1@`. Medir k/pesos com **ranx** ([docs](https://amenra.github.io/ranx/)), que também traz 25 fusões para comparar offline.
2. **Ids e hash**: adotar a regra do LightRAG (`md5(f"{len(key)}:{key}:{content}")`, doc-scoped, length-prefixed, com política de compat documentada) e separar `id` estável de `content_hash` (evitar id==hash do Haystack e o hash só-de-texto do GraphRAG). Copiar as duas gates de re-index do Onyx (timestamp → content_hash gravado após escrita) e o `human_readable_id` por run do GraphRAG para o contexto do LLM.
3. **QuoteMatch**: começar do validator do Instructor ([exact_citations](https://python.useinstructor.com/examples/exact_citations/)) + tier fuzzy com RapidFuzz `partial_ratio` ≥ 85–90 (não o 50 do FuzzyCitationEnginePack nem os 35 % do kotaemon), e âncoras `START_PHRASE/END_PHRASE` do kotaemon como formato de citação tolerante a paráfrase. Quando o gerador for Anthropic, passar cada unidade aberta como bloco custom-content e tratar `cited_text` como extrato confiável — verificando ainda o *suporte*.
4. **DerivationIntact**: HHEM-2.1-open (Apache-2.0, CPU) como checker default; MiniCheck flan-t5-large para mais precisão; LettuceDetect para localizar spans não suportados. Emprestar a semântica do Vertex Check Grounding (claim parcialmente verdadeira = não citada; `antiCitationIndices`; `groundingCheckRequired`) e o algoritmo do ALCE (recall = entailment conjunto; precision = remove-one) para a métrica de eval. O fallback `insert_citations` do RAGFlow (threshold adaptativo, near-ties, dedupe) serve como "recuperar citações ausentes".
5. **Vocabulário de status de verificação**: `Verified / Unverified / Not in Source / Numerical Error / Citation Not Found` ([citation-check-skill](https://github.com/serenakeyitan/citation-check-skill)) + taxonomia de três eixos (validade do link / relevância / exatidão) de ["Cited but Not Verified"](https://arxiv.org/abs/2605.06635).
6. **Wire format**: evento SSE `citation{id, is_new, span, payload}` do R2R + parser de stream com hold-back e code-block-awareness do Onyx ([citation_processor.py](https://github.com/onyx-dot-app/onyx/blob/main/backend/onyx/chat/citation_processor.py)); expor `search → {ids, previews}` / `fetch(id) → receipt` compatível com o contrato MCP do Deep Research para virar conector de graça.
7. **Projeção**: modelar a declaração de ontologia no `create_vectorizer` do pgai (`loading`, `chunking`, `formatting template`, `destination`, `chunk_seq`, cascade) e na rotação de chave projetada do Azure quando o pai muda; guardar `parser_config` por run (Cognita) e locators tipados como o `position_int` do RAGFlow.
8. **Eval sibling**: shape `Golden{input, expected_output, context (ideal), retrieval_context (real)}` do DeepEval; `EvaluationRunResult` + `comparative_detailed_report` do Haystack; `DAGMetric` como molde da rubrica composta; `TestsetGenerator` do Ragas pinado em 0.4.3 (ou `Synthesizer` do DeepEval, ativo) para golden sets; adicionar `citation_attribution` (TruLens) e o "citation-influence gap" do ProvenAI ([arXiv](https://arxiv.org/abs/2606.26449)) como eixos que ninguém combina.

Risco de posicionamento: a SurrealDB está construindo Spectron/Agent Memory com RRF + "provenance and trust"; é produto fechado e chunk-premised, mas vale ler o README antes de escolher nome e narrativa.
